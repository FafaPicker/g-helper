# 游戏自动性能模式

## 使用

1. 通过原有管理员启动任务运行 GHelper。Windows 的 WMI 进程启动通知需要管理员权限。
2. 点击性能模式区域“自动模式”右上角齿轮。
3. 选择 exe：使用 Windows 标准文件弹窗选择实际游戏程序；也可进入游戏后从运行进程选择，并按进程名或路径搜索。
4. 勾选需要自动切换的游戏并保存，再点击“自动模式”启用。
5. LOL 应选择实际对局进程。WeGame、Steam、Riot 启动器及 LOL 客户端不作为触发条件。

## 切换规则

- 启用或重新点击自动模式：先订阅启动事件，再检查当前游戏；有游戏切增强，无游戏切静音，不额外设置启动等待。
- 按完整路径识别已勾选的游戏。切换窗口或桌面不改变运行判定。
- 最后一个游戏退出后等待 5 秒再静音；期间有游戏运行则取消等待。
- 手动选择性能模式（包括托盘和快捷键）退出自动模式，并取消等待。
- 自动模式开关和游戏列表保存在原配置中，复用原有模式参数。
- 进程通知订阅失败或无法核实进程路径时，关闭自动模式并保留当前性能模式，不回退到轮询。

## 实现范围

监控、游戏设置窗口和退出延迟状态在 app/AutoGameMode；按钮布局集中在 app/AutoGameModeSettings.cs，便于后续调整。
启动使用过滤后的 WMI Win32_ProcessStartTrace；退出使用匹配进程的 Process.Exited，订阅 Windows 进程句柄通知。
复用已有 System.Management、性能切换接口及 AppConfig，未新增依赖。
文件选择使用 Windows 标准 OpenFileDialog，在独立 STA 线程中打开。此前未正确识别系统模态弹窗的验收判断已纠正。

## 已执行验收

- Release win-x64 独立目录发布及必要自动化测试通过，最终构建无警告或错误。
- 必要测试覆盖初次检查、立即增强、退出延迟、取消延迟、重新启用、启动器排除和两个真实子进程的退出通知。
- 本机临时进程触发实际增强模式，最后退出后约 5.2 秒切回静音；多个实例并存和取消回落通过。
- 已运行进程在重新启用自动模式时被识别，静音纠正为增强。
- 手动性能按钮和快捷键均能退出自动模式，之后进程重启不覆盖手动模式。
- 齿轮、运行进程添加、exe 路径添加、勾选保存、重新打开及取消不保存均已实测。
- 当前 DPI 和深色主题下已检查主窗口、游戏列表与内置选择器，修复表头及弹窗尺寸问题。
- 普通权限访问被拒绝时不改变性能模式；日常运行已恢复原管理员任务。

自动化测试：dotnet run --project tests/AutoGameMode/AutoGameMode.Tests.csproj
测试不访问硬件；真实进程回归仅创建并退出测试项目自身的子进程。
本机硬件切换验收使用独立的临时进程，未启动真实 LOL 对局或 Steam 游戏；具体游戏的实际进程选择及兼容性仍需在使用中确认。
原项目配置写入有约 2 秒延迟；验收切换时刻以硬件成功日志为准，而不是配置文件更新时间。
